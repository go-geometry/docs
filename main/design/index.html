Design: scipy.spatial parity

Design of item 7 of the go-scikit plan: the whole of scipy.spatial 1.18.1 plus MATLAB's computational geometry, in pure Go. Inventory, exactness decision per component, proposed repositories, waves and tasks, validation, performance and security.

You are reading the documentation of an outdated version, whose text may no longer be accurate. Go to the latest version.

Status: design, awaiting approval. No repository exists yet. The repository names below are proposals for the maintainer to approve. This page replaces the working names (hull, nearest) where it disagrees with them.

3. Qhull licence verdict

COPYING.txt (Qhull 2020.2, SPDX Qhull) allows copying, modifying and redistributing under five conditions: (1) keep all copyright notices, (2) ship the text with every copy and with every product that includes Qhull, (3) a modification notice naming who, when and why, (4) say where the original can be obtained, (5) no warranty. There is no copyleft: a Go translation is a permitted modified version, and BSD-licensed code may sit beside it. Verdict: porting is allowed. The obligation in (2) travels to every binary that links the port, so the port lives in its own repository and module (go-geometry/qhull, licence file COPYING.txt verbatim, NOTICE with the modification record “translated to Go by the go-geometry authors, , to reproduce SciPy 1.18.1 output in pure Go”), and only the packages that need Qhull import it. KDTree, distance, transform and predicates never import it.

4. Exactness decision per component

ComponentDecisionEquality target
Delaunay, ConvexHull, Voronoi, HalfspaceIntersection, SphericalVoronoiExact port of libqhull_r 2020.2 (the subset in section 2.7) and of _qhull.pyxSame simplices, same row order, same neighbors, coplanar, good; equations, area, volume bitwise against the Linux x86-64 oracle (section 6). An independent exact-predicate implementation could only promise combinatorial equivalence; for cospherical input it would choose different simplices and every consumer test written against SciPy would break.
QJ jogglePort qh_rand (Park–Miller, qh_RANDOMtype 5) and the seed logic of global_r.c:1734-1760Bitwise: the default seed is 1, not the clock. QR0/QR-1 (clock seed) are accepted but not reproducible, as in SciPy.
Delaunay transformPort of _get_barycentric_transforms (getrf, gecon, getrs; rcond < 1000·eps → NaN) using go-ndarray linalgBitwise if go-ndarray’s getrf follows the oracle’s LAPACK for n ≤ 64; otherwise tolerance 4 ulp per entry, stated in the release.
Exact predicatesIndependent, from Shewchuk 1997 and the public-domain predicates.cExact signs (never a tolerance); used to validate everything else and by the MATLAB delta.
KDTree / cKDTreeExact port of ckdtree/src and _ckdtree.pyx (BSD-3-Clause), including SciPy’s own heap (query.cxx:32-98)Distances bitwise. Indices identical, including ties, if the tree layout matches; the layout depends on std::partition and std::nth_element (build.cxx:103-121), which differ between libc++ and libstdc++. Decision: port libc++’s two algorithms (Apache-2.0 WITH LLVM-exception, compatible), giving layout equality with libc++-built wheels (task K0 verifies which wheels those are). libstdc++ (GPL-3.0 with runtime exception) is not ported: against GCC-built wheels the result is equal up to the order of exactly tied neighbours, and weighted count_neighbors sums agree to tolerance (their summation order follows the layout).
distance (pdist, cdist)Exact port of the C++ and C kernelsBitwise. The kernels reduce each pair left to right over the features and interleave 4 pairs (2 when weighted) for ILP (distance_metrics.h:49-170): SIMD goes across pairs, never across features, without FMA, so parity holds.
distance single-pair functions, directed_hausdorffPort of the NumPy expressions over go-ndarray; directed_hausdorff shuffles with go-ndarray random (MT19937 RandomState, PCG64 Generator, both present)Bitwise where go-ndarray is bitwise with NumPy; norm follows go-ndarray.
Rotation, Slerp, RigidTransform, geometric_slerp, procrustesExact port of both backendsBitwise for elementwise operations (no FMA: every product that Go could fuse is wrapped in an explicit float64(...) conversion, the rule of the Go spec). align_vectors, procrustes and mean go through go-ndarray SVD/Eigh: parity is whatever that library guarantees, stated per release.
RotationSplineExact port; needs scipy.linalg.solve_bandedBlocked on the go-scikit linear-algebra item providing solve_banded; scheduled last in its wave.
MATLAB deltaIndependent implementation on the exact predicates (MATLAB is closed source)Combinatorial equivalence and invariants against MATLAB when available and Octave otherwise; delaunayn/convhulln/voronoin go through the Qhull port with MATLAB’s default options (to be read from MathWorks in task M5).

Floating-point rule for the whole organization. The Go compiler may fuse x*y + z into an FMA on arm64, ppc64le, s390x and riscv64. Every arithmetic expression in a ported kernel and in the predicates wraps products in float64(...) so that the result does not depend on the architecture; a test per package runs the kernels on GOARCH=arm64 and amd64 and compares bits. Whether SciPy’s own arm64 builds contract FMA (clang’s default -ffp-contract=on) is not verified: task Q0 measures it. Until then the bitwise oracle is the Linux x86-64 wheel (baseline x86-64 has no FMA), and other platforms are compared combinatorially and to tolerance.

6. Validation plan

  • Oracle. SciPy 1.18.1 wheels pinned by hash, driven from a Go program that generates inputs, runs the oracle and writes JSON fixtures (the oracle never runs from shell). Bitwise oracle: manylinux_2_28_x86_64; second oracle: macosx_arm64. Octave (and MATLAB when available) for the delta.
  • SciPy’s own tests ported: test_qhull.py, test_kdtree.py, test_distance.py (with the tests/data/*.txt matrices, BSD), test_hausdorff.py, test_spherical_voronoi.py, test_slerp.py, test__procrustes.py, transform/tests/*. degenerate_pointset.npz and selfdual-4d-polytope.txt are part of the corpus.
  • Equality as section 4 states it, per component; differences are listed by name, never summarised as a count.
  • Invariants checked with exact predicates on every output: Euler characteristic, every Delaunay simplex positively oriented and with an empty circumsphere (except where Qhull reports coplanar), hull convexity, neighbour symmetry, Voronoi duality, k-NN results equal to brute force (as multisets of distances).
  • Degenerate corpora: duplicates, collinear / coplanar / cospherical sets, integer lattices, nearly-degenerate tilted lattices (Shewchuk’s “tilted grid”), points at ±1e±300, mixed scales, QJ restarts.

7. Performance plan

Single core against SciPy 1.18.1 (workers=1, OPENBLAS_NUM_THREADS=1), interleaved rounds, never at 1-min load above 8, allocation counts reported.

TableSizes
Delaunay 2-D, 3-D; ConvexHull 3-D, 6-D; Voronoi 2-Dn = 10³, 10⁴, 10⁵, 10⁶ (10⁵ in 6-D)
KDTree build, query k = 1, 16, query_ball_point, count_neighborsn = 10⁶, d = 3; n = 10⁵, d = 16
cdist/pdist per metric1000 × 1000, d = 3, 64, 1024
Rotation apply, as_euler, from_matrix, *10⁶ rotations

Order: port exactly, measure, then optimise where the table shows a gap, algorithm first. Qhull’s mem_r.c free lists become per-run slabs, qset_r sets become slices with the same element order. distance SIMD kernels go into go-simd (the lowest shared library), vectorised across pairs. Slower than SciPy is an open defect.

8. Security and fuzzing

  • Untrusted input: NaN refused (as SciPy); ±Inf refused too, a deliberate divergence (SciPy checks only NaN, _qhull.pyx:284, and hands infinities to Qhull).
  • Option strings: the Qhull option parser is fuzzed; file and trace options (TO, TI, TR, Tn output to a file) are refused.
  • Resource bounds: Delaunay output grows as n^⌈d/2⌉; every Qhull run takes a facet budget and a context.Context and returns a refusal, never an out-of-memory. Dimension limit 64 (NPY_MAXDIMS in _qhull.pyx), checked before allocation. KDTree recursion depth is bounded (the non-compact degenerate path re-enters build), leafsize ≥ 1, k ≤ n.
  • 32-bit overflow: Qhull ids are int; SciPy stores indices as intc. Counts above 2³¹−1 are refused; pdist length n(n−1)/2 is computed with checked multiplication; squareform validates sizes before allocating.
  • Bomb tests assert a refusal under GOMEMLIMIT and ulimit -v.
  • Fuzz targets: option parser, every constructor (points as raw bytes → float64), find_simplex, KDTree build+query, from_euler sequences, squareform, predicates (sign against math/big exact evaluation).
